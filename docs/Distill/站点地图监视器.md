> 站点地图监控目前处于 alpha 阶段，仅在专业版及以上计划中提供。

  
站点地图是一个重要工具，它帮助搜索引擎理解网站结构并抓取其内容。它通常包含网站的所有 URL，包括那些可能不容易被搜索引擎或访客发现的 URL。

  
站点地图有不同的格式，但最常见且广泛支持的格式是 XML 站点地图。虽然 XML 站点地图被广泛使用，但它们可能不会定期更新或自动生成。因此，如果您想接收有关新链接添加到网站上的更新，监控其站点地图文件可能无法反映当前状态，您可能会错过新内容或更新内容。为了克服这一限制，您可以使用 Distill 的爬虫来索引网站上的所有 URL。爬虫通过网站导航，就像搜索引擎一样发现和索引页面。这确保了所有 URL 都被从网站中提取出来，即使是隐藏的或动态生成的页面。

###   
使用 Distill 进行站点地图监控：工作原理

  
您可以使用站点地图监控来跟踪属于特定网站的 URL。Distill 通过使用爬虫首先创建 URL 列表来实现这一点。爬虫从源 URL 开始，搜索其中的所有链接。然后，这些链接被添加到列表中，爬虫依次访问每个链接，爬取新页面上的任何其他链接。爬虫会继续这个过程，爬取所有找到的链接，直到没有更多链接可爬。

  
然而，爬虫会抓取的链接有一些例外。它们不会抓取网站域名之外的链接，不是域名子路径的链接，或在添加时匹配 [`Exclude`](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/#exclude-links-for-crawling) 选项中提到的正则表达式的链接。通过遵循这些规则，Distill 能够创建一个全面且准确的网站所有 URL 列表，这些 URL 可以进行变化监控。

###   
创建和监控网站地图

  
如果您需要监控网站链接的任何更新，您只需要创建一个网站地图监控器。但是，如果您还需要监控这些 URL 的内容，请按照以下两个步骤操作：

1. **爬取** ：查找网站上的所有链接，并创建一个已爬取 URL 的列表。您可以在这一阶段设置爬取器的频率和排除项。这将创建用于监控的网站地图。
2. **监控** ：您可以使用 Change History 下的 **[导入监控器](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/#import-and-monitor-crawled-urls)** 选项，从列表中选择已爬取的链接，并将它们导入到您的监控列表中。"

###   
使用爬虫进行网站链接监控

  
使用爬虫监控网站地图的步骤如下：

1. 从 Web 应用中打开监控列表：[https://monitor.distill.io](https://monitor.distill.io/)
2. 点击 `Add Monitor`\-> `Sitemap`。
	![button to add a sitemap monitor](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/add-sitemap-monitor.jpg)
3. 在源页面中，添加起始 URL。链接将从相同的子域名和相同的子路径中抓取，而不是完整域名。因此，您可以添加您希望开始抓取的 URL。例如，如果 URL 是 [https://distill.io](https://distill.io/)，所有子路径如 [https://distill.io/blog](https://distill.io/blog)、[https://distill.io/help](https://distill.io/help) 等将被抓取。但它不会抓取像 [https://forums.distill.io](https://forums.distill.io/) 这样的 URL，因为它是一个独立的子域名。
4. 如果您想排除任何用于监控的链接，可以使用下面提到的正则表达式过滤器进行排除。
5. 点击“完成”。这将打开监控配置的选项页面。您可以在该页面配置操作和条件。完成后保存。

  
每当网站地图中的 URL 被添加或删除时，您都会收到变更提醒。通过点击预览，您可以查看网站地图监控器的变更历史。

![Change history of a sitemap monitor](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/sitemap-changes.jpg)

###   
排除用于爬取的链接

  
您可以使用正则表达式过滤器来排除不需要爬取的链接。当您首次为站点地图监控设置爬虫时，此选项可在源页面上找到。或者，您可以从详细信息页面修改任何现有爬虫的配置。默认情况下，所有图像链接都被排除在爬取之外。![Regex filter for exclusion](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/regex-for-exclusion.jpg)

### 爬取频率

  
默认情况下，爬取频率设置为1天。但是，您可以根据需要修改爬取频率。您可以通过以下方式执行此操作：导航到爬虫页面。

![view crawler's detail page](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/view-crawler.jpg)

  
然后你可以点击“编辑爬虫”选项来更改计划。

![edit crawler's config](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/crawler-config.jpg)

###   
页面宏：在页面被爬取前执行步骤

  
在开始爬取之前，通常需要对页面进行验证。宏将在爬取每个页面之前运行。

  
添加页面宏的步骤：

1. 点击监控列表中的汉堡图标 -> 选择 `Crawlers`。
2. 点击要添加页面宏的爬虫 -> 点击 `Edit Crawler`。
3. 在"页面宏"旁边点击 `Edit Steps`。
![Adding steps to be executed before crawling a page](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/page-macros-in-sitemap.jpg)

4. 您可以在 URL 被爬取之前添加您想要执行的步骤。

####   
页面宏的用例

#####   
当网站不可用时终止爬取任务

  
当页面暂时不可用（出现 503 错误）时，加载的页面将不包含原始链接。如果这些链接被成功抓取，最终抓取的链接列表将是不完整的。这将触发一个错误警报。为防止这种情况发生，爬虫应该停止抓取。这可以通过引发一个错误来实现。这可以通过在 `Page Macro` 中添加验证来实现。

1. 添加一个 `assert` 步骤，点击尖头图标以展开选项。
2. 检查 `element_has_text`，并输入网站可能用来表示维护的一般关键词，例如“维护”。
3. 点击 `  设置可选参数  ` 并输入你想显示的错误信息，例如：“爬虫停止：网站维护中”。
![Stop crawl when under maintenance](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/error-crawl-of-sitemap.jpg)

####   
根据页面内容跳过 URL

  
在某些情况下，你可能希望根据特定标准跳过爬取 URL，以避免无关的爬虫通知。例如，在监控可用产品列表时，你可以跳过库存不足产品的 URL。以下步骤展示了如何操作：

1. 添加一个 `if...else` 块。
2. 检查 `element_has_text` 是否包含“in stock”，并使用溢出按钮来否定这个步骤。这将向您的模块添加一个 `NOT`。
3. 在条件体中使用 `skipURL`。

  
页面宏中的这个否定将跳过所有不包含“有货”文本的 URL。

![Stop crawling irrelevant pages](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/negate-skip-crawler.jpg)

### URL 重写

  
URL 重写通过在爬取前修改 URL 来优化爬取。这个过程可以规范化具有重复页面的网站的 URL，管理重定向，并将多个 URL 合并为一个首选版本。

  
对于常见的 URL 重写情况，您可以使用以下“预设”：

**测试 URL： `https://example.com/products?size=10&color=blue&category=shoes`**

1. **排序查询参数** ：按升序排序查询参数。
	  
	**重建的 URL：** `https://example.com/products?category=shoes&color=blue&size=10`
	  
	排序查询参数后，您需要使用 ` 返回构建的 URL` 预设。
2. **删除所有查询参数** ：从 URL 中删除所有查询参数。
	  
	**重建的 URL：**`https://example.com/products`
3. **返回构建的 URL**：根据指定的函数，返回重建后的 URL。

**重写 URL 的步骤：**

1. 在爬虫中导航并点击“编辑爬虫”。
2. 在“重写 URL”旁边点击“编辑步骤”。
![Rewrite URL](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/url-rewrite.jpg)

3. 你可以选择使用不同的预设。![Rewrite URL](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/url-rewrite-preset.jpg)
	![Rewrite URL](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/presets-url-rewrite.jpg)

###   
URL 重写用例

####   
通过排序查询参数消除重复 URL

  
查询字符串中包含多个参数的 URL 可能会导致网络爬虫将它们识别为不同的页面，即使它们指向相同的内容。这是因为参数的顺序不同。通过规范化这些 URL——将参数按预设顺序排序——并将它们合并为一个站点地图条目，我们可以防止重复条目错误通知。

  
例如，爬虫可能会发现以下两个 URL 指向同一页面：

- `https://bookstore.com/search?sort=price_asc&category=fiction`
- `https://bookstore.com/search?category=fiction&sort=price_asc`

  
在两个 URL 中，第一个 URL 中的 `sort` 参数位于 `category` 参数之前，而第二个 URL 中位于之后，但两者都导致按价格升序搜索虚构书籍。规范化这些 URL 确保它们在站点地图中被识别为相同的条目。

  
您可以使用 URL 重写来组织和优化 URL：

![Stop crawl when under maintenance](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/sort-url-rewrite.jpg)

1. 点击 URL 重写中的 `Edit Steps`。
2. 选择预设 `Sort Query Params`。
3. 然后，从预设中点击 `Return Constructed URL`。
4. 注意到在重写函数执行后，URL 中的参数现在已按爬虫排序。

  
确保最终步骤输出一个完整且有效的 URL。例如，`return join_url_fragments` 函数将 URL 的不同部分（如哈希、路径和查询）与原点结合，组合成一个完整的 URL。这确保了你一直在处理的各个 URL 组件能够正确地连接在一起，形成一个有效且完整的 URL。

| **爬虫状态** | **描述** |
| --- | --- |
| `Total` | 在网站地图中找到的 URL 总数。 |

| `Crawled` | 已成功爬取的 URL 数量。 |
| `Errored` | 在爬取过程中遇到错误的 URL 数量。 |

4. 点击任务的 `Started on` 字段。它会显示爬虫在该次运行中找到的 URL 列表。它还会显示每个 URL 的状态，表明是否已被爬取。

###   
导入并监控爬取的 URL

  
当站点地图监控器完成对您网站所有链接的抓取后，您可以在“变更历史记录”部分访问**导入监控器**按钮，如下所示：

![Import Monitors button](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/d033-import-monitors.jpg)

  
点击此按钮将显示所有已抓取链接的列表以及附加详细信息。您可以通过选择**显示所有 URL** 来筛选列表，仅查看当前未被监控的 URL。

  
选择您要监控的链接后，点击**导入选定监控器**按钮，并配置选项页面以完成导入。

![import monitors button](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/d033-select-monitors-to-import.jpg)

### 导出抓取的 URL

  
你可以按照以下步骤将爬取的 URL 导出为 CSV 格式：

1. 从你的监控列表中，点击站点地图监控的预览。
2. 点击`下载`按钮导出数据。![export URLs to CSV](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/site-map.jpg)

  
这将下载爬虫找到的 URL 列表。CSV 文件将包含以下字段：URL、内容类型、状态码和差异类型。“差异类型”字段表示与上次爬取相比的变化：

- **新增** : 新发现的 URL
- **未变** : 之前爬取中存在的 URL
- **删除** : 已被移除的 URL
![export URLs to CSV](https://distill.io/docs/web-monitor/sitemap-monitor-using-a-crawler/images/site-map-csv.jpg)

###   
爬虫数据是如何清理的

  
爬虫任务每次运行都会生成大量数据。为了有效管理这些数据，已建立一套系统清理流程。具体来说，仅保留最新的10个任务，而删除先前任务的超额数据。

  
然而，过去检测到变化的任务会保留，直到变更历史被截断。这确保用户可以访问重要的历史任务数据，即使这些数据超出了最新的10个任务。
