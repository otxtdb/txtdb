条件允许您仅在更改符合您的标准时接收警报，从而减少不重要的通知。

## 条件的工作原理

  
当且仅当以下两个条件同时满足时，才会触发警报：

1. **变化检测** : 监控的网页上发生了变化。
2. **条件评估** ：变更满足定义的全局和本地条件。

  
这一要求使警报保持相关性和意义。

## 示例

### 价格警报

- **场景** ：当某物品的价格从当前的 80 美元下降到 70 美元以下时，接收警报。
- **无条件** ：对任何价格变动都会发出警报。
- **使用条件** ：仅当价格低于 70 美元时设置警报。` 添加的文本小于 70`。

### 关键词监控

- **场景** : 您希望仅在监控文本包含特定关键词时收到警报。
- **使用条件** : 添加一个条件，指定只有在添加的文本包含“yourkeyword”时才触发警报。您可以添加多个条件以涵盖各种关键词。` 添加文本包含 keyword1``OR`` 添加文本包含 keyword2`。

##   
全局和本地条件

  
全局条件适用于您监控列表中的每个监控项。

  
要打开全局条件：

1. 在监控列表中，点击汉堡图标。
2. 选择 **全局条件** 。
![Global conditions Option](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-global-condition.png)

  
本地条件适用于单个显示器。当两种类型都存在时，警报必须满足每一个。

##   
添加或删除条件

  
使用以下步骤在显示器上管理条件：

1. 点击显示器上的菜单按钮。
![Conditions - Distill Web Monitor](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-open-options.png)

2. 选择 **编辑选项** 。
3. 点击 **添加条件** 创建规则，或点击旁边的叉号图标删除它。
![Conditions - Distill Web Monitor](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-add-condition.png)

4. 保存您的更改。

### 文本类型

  
以下是可应用条件进行评估的不同文本类型。

####   
示例 - 监控内容的变化

- **原文** : “Distill 是一款很棒的网页监控应用”
- **更新后的文本** : “Distill 是最好的网页监控应用”

  
这是它在变更历史中的显示方式。默认情况下，变更历史会以绿色突出显示添加的文本。删除的文本没有显示为 `Deleted` 是因为在变更历史中未勾选“删除”选项。

![Conditions - Distill Web Monitor](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-change-history.png)

  
根据上述示例，下面是一个显示不同文本类型值的表格。注意示例中单词“web”位置的变化，这会影响 `Added Text` 和 `Net Added Text` 的值。

| 文本类型 | 描述 | 基于上述示例的值 |
| --- | --- | --- |
| `Text` | 将条件应用于整个监控文本，适用于全面内容分析。 | `Distill is the best web monitoring app` |
| `添加的文本 `*(首选)* | 仅针对最新更改后添加的文本，适用于增量更新或添加。 **用例：** 当文档中添加新关键词时触发通知。 | `the best web` |
| `Deleted Text` | 关注最新更新期间删除的文本，对于追踪内容删除至关重要。 **用例：** 当政策文档中删除特定术语时发出警报。 | `an awesome for web` |
| `Previous Text` | 条件是在最新更改之前的全部文本上评估的。 | `Distill is an awesome monitoring app for web` |
| `Net Added` | 根据添加的文本进行评估，并忽略文本的重新排序。 **应用场景：** 非常适合经常重新排序文本部分的动态内容，如新闻源、产品列表和票务网站。 [应用场景](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/#ignore-reordering) | `the best` |
| `Net Deleted` | 功能类似于 `Net Added`，忽略文本的重新排序。 **使用场景：** 非常适合经常重新排序文本部分的动态内容，如新闻源、产品列表和票务网站。 | `an awesome for` |

  
你可以从变更历史中点击铃铛图标查看不同文本类型的值。你也可以查看条件（如果设置）是如何被评估以触发警报的。

### 条件类型

  
以下是 Distill 最新版本中可用的条件类型。您可以根据需求使用一个或多个条件类型。

| 类型 | 描述 |
| --- | --- |
| `contains` | 检查文本是否包含指定的关键词或短语。 |
| `does not contain` | 验证文本不包含指定的关键词或短语，类似于 `contains`。 |
| `starts with` | 判断文本是否以指定的文本开头。 |
| `doesn't start with` | 确保文本不以指定的文本开头。 |
| `ends with` | 检查文本是否以指定的文本结尾。 |
| `doesn't end with` | 确认文本不以指定的关键词或短语结尾。 |
| `is empty` | 验证文本是否为空。 |
| `is not empty` | 确认文本不为空。 |
| `has number less than (<)` | 当文本中的数值小于指定数值时适用。 |
| `has number more than (>)` | 判断数值是否增加了超过指定数量。 |
| `has number that decreased more than` | 检查数值是否减少了超过指定数量。 |
| `has number that increased more than` | 判断数值是否增加了超过指定的量。 |
| `has number that decreased more than percentage (%)` | 验证数值是否减少了超过指定的百分比。 |
| `has number that increased more than percentage (%)` | 检查数值是否增加了超过指定的百分比。 |
| `length is less than` | 适用于文本长度（字符数）小于指定数量的文本。 |
| `length is greater than` | 适用于文本长度大于指定字符数的文本。 |
| `matches regular expression` | 允许将文本与指定的正则表达式模式进行匹配。这可用于区分大小写的匹配。`gim` 标志可以根据需要添加。`g` 代表全局，`i` 代表不区分大小写，`m` 代表多行。 **用法：** `matches regular expression \w+` 检查一个或多个单词字符（a–z，A–Z，0–9，\_）。 |
| `doesn't match regular expression` | 用于文本不应匹配指定正则表达式模式的情况。 |
| `doesn't match any previous text` | 用于跟踪最新文本更改是否与更改历史中的任何先前更新不同。 [用例](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/#not-in-prev-text) |

  
您可以包含多个条件以满足您的特定需求，使用 `AND` 或 `OR` 将它们分隔。使用 `AND` 要求所有条件都为真。使用 `OR` 要求至少有一个条件为真。

**注意：**

1. 在 Distill 中，条件默认为 **不区分大小写** 。
2. 数值条件（小于、大于等）如果选择中包含 1 个数值内容，则效果很好。在选择中包含多个数字的情况下，数值条件将对选择中的每个数字进行评估，并在任何匹配时返回 True。

###   
数值条件的数字格式

  
为确保对数值数据的准确评估，我们的系统默认采用美国数值格式（例如，一千表示为1,000.00）。如果你的数据使用不同的数值格式，例如欧洲格式（例如，一千表示为1.000,00），请在条件中选取相应的格式。此设置确保数值比较和计算能够根据你的地区标准正确执行。

###   
通知状态和条件调试器

  
Distill 中的[变更历史](https://distill.io/docs/web-monitor/change-history-and-highlighted-changes/)会记录所有检测到的变更，无论它们是否匹配任何条件。

  
当变更满足条件中定义的标准时，会发生以下操作：

- 触发警报（例如，电子邮件、推送通知，如果已配置）。
- 监控器的状态变为“未读。”
- 一个**铃铛图标**出现在变更历史中，表示已触发通知。

  
点击铃铛图标会打开**条件调试器**窗口，该窗口显示条件评估的结果。如果最终评估结果为 `True`，则会执行配置的操作。

![Alert Trigger Status](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-alert-trigger-status.png)

  
以下示例展示了点击触发警报的铃铛图标后条件调试器的输出：

![Condition Evaluation Details](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-which-condition-triggered-alert.png)

  
如果变更**不**符合条件标准，铃铛图标将处于未触发状态。您仍然可以点击图标查看条件评估详情，了解其未触发警报的原因。

##   
文本警报的常见用例

####   
仅对文本添加进行警报

- `Added text` `is not Empty`

####   
对微小变化不进行警报

- `添加文本``长度大于 ``10`.
- 此条件将检查字符长度是否大于10。

####   
仅对价格上涨发出警报

  
`添加文本 ` `has number that increased more than` `0`

#### 区分大小写的匹配

  
`添加文本``匹配正则表达式 ``your-keyword` with `gm` (标志)

####   
仅对字母变化发出警报

- `添加的文本``匹配正则表达式 ``[a-zA-Z]{1,}` with `gim` (标志)
- 这将对涉及字母的变化发出警报，而忽略数字或日期的变化。上述正则表达式将匹配一个或多个字母字符的出现。
![Regex condition](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-regex-example.png)

#### 数值变化警报

- `添加的文本``匹配正则表达式 ``[0-9]{1,}`
- 上述正则表达式将匹配一个或多个数字字符。

####   
为变更告警添加多个关键字

- `Added Text matches regular expression` `keyword1|keyword2|keyword3|keyword4` 使用 `gim`(标志)
- 在使用带 `gim` 标志的正则表达式时，所有关键字都使用竖线 (|) 分隔。您也可以使用 `contains` 条件类型来使用多个条件。

####   
如果最新更新在变更历史中是唯一的，则发出警报

- `doesn't match any previous text` 运算符可用于检查最新文本变更是否与变更历史中的任何先前更新不同。例如：在监控职位列表时，如果职位会间歇性地被添加或删除，此运算符会过滤掉由这些变更引起的不必要警报。

  
示例：这是条件的截图：

![Condition window showing text does not matche previous text](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-condition-text-does-not-match-previous.png)

  
对于上述条件，最新的变更不会触发任何警报，因为它完全匹配变更历史中的先前记录。

![Text matches previous text](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/images/d013-text-matches-previous-text.png)

####   
仅跟踪文本的净变化，忽略文本的重新排序或移动

- `Net Added``  不为空  `。例如：之前的文本：ABC，更改后的文本：BDC。这将仅对添加的文本“D”触发变更提醒，而忽略“B”、“C”的位置变化以及删除的“A”。如果 ABC 变为 CAB，则不会触发提醒，因为这只是顺序变化，没有添加或删除内容。
- `Net Deleted``  不为空  `。例如：原文：ABC，修改后：BDC。这将仅触发删除文本“A”的变更提醒，而忽略"B"、"C"的位置变化及新增文本“D”。
- 同时满足上述两个条件的复合条件将分别对新增文本“D”和删除文本“A”发出提醒，而忽略"B"和"C"的位置变化。

###   
常见问题排查

  
为有效排查和优化您的提醒条件，请遵循以下步骤：

1. 查看变更历史：访问您的监控器的变更历史，以了解已检测到的变更。这些洞察可以帮助您确定警报为何被触发或未被触发。
2. 条件评估：点击变更历史记录中的[铃铛图标](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/#how-to-find-out-which-condition-triggered-the-alert) ，查看每个检测到的变更的条件评估方式。这可以帮助您找出条件设置中的不准确之处。
3. 修改条件：根据您的审查，调整您的条件以更好地匹配您的监控需求。考虑简化或指定您的选择，以实现更精确的监控。

## 常见问题解答

  
关键词显示在页面上但警报没有触发

  
当监控页面上检测到变化时，会触发警报。如果页面内容保持不变，即使页面上存在关键词，也不会触发警报。这确保了警报是有意义的，并且只与新的变化相关。

  
即使移除条件后也没有收到警报

  
有可能全局条件正在影响你的警报。检查你是否设置了适用于所有监控器的[全局条件](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/#global-and-local-conditions) 。

  
数值条件触发不想要的警报

  
数值条件在目标选择为单个数值时最为适用。如果存在多个数值，条件会独立评估每个数值，可能导致误报。为避免这种情况，请将选择范围限定为感兴趣的数值，这样可以确保警报的准确性和相关性。

  
如何忽略由于文本位置变化而触发的更改？

  
使用 \`Net Added\` \`不为空\` 和 \`Net Deleted\` \`不为空\` 作为条件。这些运算符会忽略由于文本移动和重新排序导致的文本片段变化。只有当跟踪的段落有净变化时，才会给你发出警报。

  
如何忽略翻转的文本变化？

  
使用 \`text\` \`不匹配任何之前的文本\`。请查看 [这个](https://distill.io/docs/web-monitor/using-conditions-to-get-alert-on-important-changes/#not-in-prev-text) 获取更多详细信息。
