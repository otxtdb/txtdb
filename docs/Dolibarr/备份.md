##  [![Who.png](https://wiki.dolibarr.org/images/9/9b/Who.png)](https://wiki.dolibarr.org/index.php/File:Who.png)为什么？

有多个原因说明为什么备份 Dolibarr 的完整实例很重要。例如：

- 因为你计划进行升级，如果升级失败，想要回退到之前的版本。
- 因为你想把 Dolibarr 从一个服务器迁移到另一个服务器。
- 当然，如果发生不好的事情（如磁盘崩溃、黑客攻击损坏等），能够进行恢复以确保安全。

由于以上所有原因，建议定期备份 Dolibarr 使用和保存的所有数据。

##  [![Who.png](https://wiki.dolibarr.org/images/9/9b/Who.png)](https://wiki.dolibarr.org/index.php/File:Who.png)要保存什么？

Dolibarr 将其数据保存在 3 个不同的空间中。在每次版本升级之前，所有这些空间都必须保存，以确保在出现问题时或想要回退到先前版本时能够恢复数据。这是您需要保存的 3 种数据类型，以确保不会丢失任何数据。

### A) 数据库

数据库包含您从 Dolibarr 屏幕中添加的所有数据（不包括下一章中介绍的附加/生成的文件）。保存数据库必须以全局方式（所有内容）进行。建议定期保存数据库。请参阅本文档后面的“如何”章节。

### B) 文件

所有与您的 Dolibarr 实例相关的文件都保存在配置文件 _dolibarrdir/htdocs/conf/conf.php_ 中定义的目录中。如果您在首次安装时保留了默认选项，它应该是类似于 _dolibarrdir/documents_ 的路径。此目录必须完全保存。在执行升级时，升级过程不应更改此目录，但此目录可以随时被 Web 服务器读取和写入，它可能会因恶意操作或错误而更改。为确保保留所有附加文件，并在它们意外删除或更改时能够恢复，只需复制此目录中的所有内容即可。

_注意_ ：复制包含所有您文档的整个文件夹可能是一个耗时的过程，所以如果您无法定期执行此操作，至少备份您的数据库（它应该要小得多，并且仍然能够使您恢复大部分数据，然后您可以使用这些数据来重新生成大部分文档）。

### C) 配置文件

配置文件不应由升级过程修改，但在升级时保存它更为明智。配置文件名为 _conf.php_，您可以在目录 _dolibarrdir/htdocs/conf/_ 中找到它。将这个文件复制到您的备份的专用区域。

_注意_ ：然而，这个备份是可选的，因为如果您知道您的数据库凭证，仍然可以手动从零开始重建这个文件，或者使用 Dolibarr 安装向导。在执行恢复操作时，仍然可以通过从头开始安装来重建这个文件。

### D) 代码更改

最后，任何模块的自定义开发，即所有为满足特定需求而添加或修改的 php 文件（或其他文件）也应该被保存。在大多数情况下，你不需要担心这一点。

##  [![Who.png](https://wiki.dolibarr.org/images/9/9b/Who.png)](https://wiki.dolibarr.org/index.php/File:Who.png)何时？

备份的频率取决于你使用 Dolibarr 的频率以及你愿意在发生意外时损失多少数据。频率越高，在系统崩溃或故障时损失的数据就越少。

此外，你可以选择对更关键的部分（如数据库）进行更频繁的备份，而对其他较重的部分（如文档）进行较少规律的备份。

作为一个好的起点，你的数据库应该每月备份一次，甚至根据你的使用情况每周备份一次，而文档可以根据你的使用情况每半年或每月备份一次。

此外，conf.php 文件只需要备份一次（因为它只有在您更改主机时才会更改，无论如何都可以手动创建）。

##  [![Who.png](https://wiki.dolibarr.org/images/9/9b/Who.png)](https://wiki.dolibarr.org/index.php/File:Who.png)怎么办？

### A) 数据库

备份数据库有4种方法：

#### 使用 Dolibarr 系统备份工具

这是最简单的备份方式，此外所有备份都将存储在服务器上并会列出，以便您可以随时恢复任何版本。

如果你使用的是足够新版本的 Dolibarr，只需使用管理员账户登录 Dolibarr（只有管理员可以使用系统工具）。

然后进入**主页 -> 系统工具 -> 备份** 。选择你的备份选项（你可以保留所有默认值）。

_替代方案_ ：默认方法 **MySQL 转储（mysqldump）** 也需要你能够访问服务器上可执行的 mysqldump 二进制文件。如果你在禁用 mysqldump 使用的共享主机上，可以尝试其他方法，称为 **MySQL 转储（php）**。这种方法不能保证 100%成功，所以请先自行尝试，通过创建备份并在本地非生产服务器上恢复来检查你的数据是否正确保存。

#### 使用 mysqldump

如果你更喜欢手动模式，也可以使用为你的数据库设计的备份工具。使用 Mysql，将数据库备份到文件的命令是：

mysqldump -u user -pyourpass -l --single-transaction -K --add-drop-table=TRUE --tables -c -e --hex-blob --default-character-set=utf8  --result-file=mysqldump_databasename_version_date.sql databasename

where :

- _user_ 是 Dolibarr 用于连接数据库的 MySQL 用户，
- _yourpass_ 是 MySQL 账户 user 的密码（警告，p 和 yourpass 之间不能有空格），
- _databasename_ 是 Dolibarr 数据库名称。

这些信息（用户、密码和数据库名称）可以在您的配置文件 _dolibarrdir/htdocs/conf/conf.php_ 中找到。

结果文件（"备份文件"），称为 mysqldump_databasename_version_date.sql，其中

- _版本_ 是 dolibarr 版本（例如：3.7）。
- _日期_ 可以用日期替换，推荐格式为 YYYYMMDD，其中 YYYY 是年份（例如：2011），MM 是月份编号（例如：05），DD 是月份中的日期（例如：18）。

使用示例值，我们将得到一个名为 _mysqldump_databasename_3.7_20110518.sql._ 的备份文件

  
如果你希望文件被压缩（压缩）：

mysqldump databasename -h host -u user -pyourpass -l --single-transaction -K --add-drop-table=TRUE --tables -c -e --hex-blob --default-character-set=utf8 | bzip2 > mysqldump_databasename_version_date.bz2

转储文件将以 bzip 压缩格式生成。

**示例：**

在 Linux 系统中，要在每天 1:30 进行常规备份到文件mysqldump_databasename_DD.sql.bz2，你可以将以下内容添加到你的 cron 文件中：

30 1 * * * mysqldump databasename -h host -u user -pyourpass -l --single-transaction -K --add-drop-table=TRUE --tables -c -e --hex-blob --default-character-set=utf8 | bzip2 > mysqldump_databasename_`date +%d`.sql.bz2

#### 使用 phpMyAdmin

首先，避免使用 phpMyAdmin 来保存你的数据库！phpMyAdmin 会生成一些转储文件，但如果使用默认选项， **你将无法恢复它** 。你必须启用一个特定选项，以便之后能够恢复你的备份（如果你忘记这样做，并且已经有一个想要恢复的备份，请阅读下面关于 FOREIGN_KEY_CHECKS 的注释）。

在 phpMyAdmin 中，点击**导出**标签，然后选择您的 Dolibarr 数据库/表（取决于您是在多数据库视图还是表视图），然后**启用****禁用外键检查**选项，同时确认输出格式为 SQL，然后您可以验证您的导出。请注意，即使使用此选项，phpMyAdmin 的备份也永远无法保证，并且经常无效。唯一安全的方法是使用 mysqldump（从 Dolibarr 或手动使用。参见前两章）。

#### 使用其他第三方工具

您也可以使用第三方数据库备份软件，例如可以上传到服务器的 php 脚本（如 Howard Yeend 的 db2SQL 或 BigDump），或者使用数据库设计/工作台软件，这些软件通常提供远程连接到您的数据库的功能，并允许您进行完整备份（以及远程管理您的数据库）。

### B) 文件

只需将 Documents 文件夹（默认为 _dolibarr/documents_）复制到您的本地备份目录。

注意：如果您使用 Dolibarr 的系统工具备份了数据库，sql 导出文件也位于 Documents 文件夹中，因此也会被复制。

  

### C) 配置文件

将文件 _conf/conf.php_ 复制到专门用于备份的目录中就足够了。

这个文件中唯一重要的值是文件 **conf/conf.php** 中找到的条目键 **dolibarr_main_dolcrypt_key**。一些敏感的数据库数据使用这个键在数据库中加密。没有它，系统恢复仍然是可能的，但敏感数据（令牌、BAN）将保持模糊；你需要重新生成它。
