## 概述 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#overview)

Nextcloud 每年发布多个主要版本，但通过“较轻”的维护更新为每个主要版本提供一年的支持（并定期[回滚](https://en.wikipedia.org/wiki/Backporting)适用的安全性和错误修复）。这允许高速的开发节奏，同时仍然为管理员在规划部署、升级和维护活动时提供灵活性。

详细的[即将到来的主要和维护发布计划 ](https://github.com/nextcloud/server/wiki/Maintenance-and-Release-Schedule)（以及生命周期结束预测）会定期更新，以促进部署、测试和升级计划的制定。

无论您想要最新的功能和优化，想要帮助测试，还是只想等到一切准备就绪，您都有选择，可以决定最初部署 Nextcloud Server 的版本以及进行主要升级的频率。

危险

我们始终建议尽快安装最新的**维护**版本，无论您使用的是 Nextcloud 服务器的哪个主要版本。我们还始终强烈建议尽快从**生命周期结束**版本升级。

提示

通过 Nextcloud 开发者通过 [Nextcloud GmbH](https://nextcloud.com/) 提供的[企业支持订阅选项 ](https://nextcloud.com/enterprise/)，可以获取扩展维护和额外支持。

## 发布类型 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#release-types)

Nextcloud 在默认发布渠道中有两种类型的发布：

1. 主要发布
2. 维护发布

**主要**版本的 Nextcloud Server（例如 `28.X.X`）引入了新功能和功能。

每个主要版本都通过定期的维护版本（例如 `X.X.4`）支持**一年** ，这些维护版本会修复关键错误和安全漏洞。

### 主要版本 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#major-releases)

主要版本通常引入新功能，并且经常也包含“底层”的变更。这些变更可能非常广泛。

特定主要版本由版本字符串的第一部分表示。例如，Nextcloud Server `28.0.4` 是主要版本 `28`。而 `27.1.7` 是主要版本 `27`。

提示

编号最高的主要版本提供最新功能。而编号最低的主要版本则提供最长时间的市场应用。

注意

在更新器提供新主要版本之前，您可能需要满足新的系统要求。即使提供了新版本，也可能需要其他更改，而更新器无法完全检查。我们尝试在每个新版本的《管理员手册》中，在《发布说明》章节的“重大变更”部分中突出显示这些内容。

警告

应用程序通常根据它们所支持的 Nextcloud 服务器的主版本来定义其兼容性。在选择要部署的主版本或决定何时升级到新发布的主版本之前，请考虑您最喜爱的关键应用程序与 Nextcloud 服务器未来主版本的兼容性。此外，由于许多应用程序是由社区提供并由志愿者维护的，因此您可能希望主动测试应用程序以针对 Nextcloud 的新主版本（或者如果您有能力，则对其进行适配），以鼓励更快（或更高质量）的发布。

### 维护版本 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#maintenance-releases)

维护版本故意**不**引入新功能或破坏性变更。这是为了降低部署更新的风险和影响，以便能够快速且常规地解决关键错误或安全漏洞。

维护版本会发布（通常同时发布）给所有尚未达到生命周期结束状态的稳定主要版本。

这些版本不应存在应用兼容性问题，也不应引入需要重新培训最终用户的变化。

特定维护版本由版本号的最后一部分表示。例如，`28.0.4` 是 Nextcloud Server 主要版本 `28` 的第四次维护版本。它提供了自上次维护版本（在本例中为 `28.0.3`）以来解决的任何关键错误和安全漏洞的修复。

注意

所有关键错误修复，包括与安全相关的修复，都会[回滚](https://en.wikipedia.org/wiki/Backporting)到**所有**维护中的主要版本。

## 发布计划 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#release-schedule)

Nextcloud Server 的新**主要**版本大约每十六周发布一次。

新的**维护**版本大约每四周发布一次。

### 支持期限（“维护”）[](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#length-of-support-maintenance)

我们的发布计划意味着多个主要版本（例如 26.X.X、27.X.X、28.X.X）同时得到支持。每当解决一个关键错误或漏洞时，如果它影响超过一个主要版本，它会被**回退**到所有适用的主要版本，并在下一个维护版本中发布（例如 `28.0.3` -> `28.0.4`）。任何尚未达到生命周期结束状态的主要版本都会收到这些维护更新。

这种重叠的发布计划以及可预测的节奏允许快速开发，同时为管理员提供可见性、访问关键错误修复的途径，以及在如何积极升级到新主要版本方面的灵活性。

注意

自从每个主要版本从发布之日起支持一年，为了保持更新，你至少需要做的是安装发布时发布的维护版本，并在你当前使用的版本达到生命周期结束状态时升级到下一个更高版本的主要版本。由于维护版本仅通过最新错误和安全漏洞修复来修补你的服务器——并且**不**引入其他重大变化——升级到新的维护版本的风险远低于升级到新的主要版本。

### 生命周期结束 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#end-of-life)

生命周期结束状态意味着支持/维护结束。主要版本在初始发布一周年时停止发布维护版本。该主要版本随后进入生命周期结束状态，将不再接收任何错误修复或安全漏洞修正。

注意

通过 Nextcloud 开发者通过 Nextcloud GmbH 提供的企业订阅服务，可以延长对主要版本的支持。

所有主要版本的生命结束日期都会提前发布，以方便规划。

注意

只要一个主要版本仍然列在维护计划中，被标记为 *当前维护* ，你就可以预期会收到所有相关的关键错误或安全漏洞修复（即使这些修复也提供给更新的主要版本，如果它们与仍然受支持较早的主要版本相关）。

## 安装版本 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#installation-version)

由于每年发布多个主要版本，并且每个版本都支持一年，包括任何相关的错误和安全修复，因此您可以根据自己的判断选择最初部署哪个主要版本，以及何时升级到新的主要版本。

注意

如果您计划在企业环境中部署 Nextcloud，并且您的使用是关键任务，开发人员可以通过[企业服务协议](https://nextcloud.com/enterprise/)帮助您选择最适合您特定用例的主要版本，并帮助确保其得到最佳部署，同时解决您可能遇到的任何关键问题。

## 发布渠道 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#release-channels)

默认情况下，所有 Nextcloud 安装都使用`稳定`发布渠道。该渠道以最低风险为大多数用户提供最新的功能。

注意

Nextcloud 会分阶段推出新版本，以进一步降低大规模更新的风险。新版本，尤其是主要版本，通常最初只提供给一小部分系统。在一周（或更长时间）内没有报告出现大规模严重错误后，将向更多系统提供更新。有时主要版本会限制在 <100% 的系统上，直到第一个维护（错误修复）版本发布之后。

警告

在使用 `稳定 `渠道时，即使您现有的主要版本尚未达到生命终结，也有可能被 *提供* 更新的主要版本以进行升级。是否在此时升级或等待更好的时机部署主要新版本，取决于您自己的决定。另一方面，新的 **维护** 版本（在您当前运行的主要版本内）应尽快部署，以保持与安全更新和其他关键错误修复同步。

危险

确保你正在运行一个活跃维护的**主要**版本至关重要。一旦主要版本达到生命终结状态，它将不再接收任何进一步的维护版本来修正关键错误或漏洞。

您可以在我们定期更新的[维护和发布计划](https://github.com/nextcloud/server/wiki/Maintenance-and-Release-Schedule)中找到所有稳定频道主要版本和维护版本的详细计划，包括终止日期。

## 主要版本升级 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#major-version-upgrades)

在从一个大版本升级到另一个大版本之前，我们强烈建议您查看**发布说明**章节中的*重大变更*部分，以最大程度地降低在您的环境中引入意外破坏性变更的可能性。

警告

通常建议做好数据备份（并测试数据恢复方法！），但在执行更新（无论是主要版本还是维护版本）之前，这一点尤其重要。

## Beta 版本和候选版本 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#beta-releases-and-release-candidates)

在发布一个新的最终主要版本之前，通常至少会发布四个测试版本，然后是两个候选版本，每个版本之间间隔一周。

在发布一个新的最终维护版本之前，大约会提前一周发布一个候选版本。

每个版本的预期日期可以在[详细日程](https://github.com/nextcloud/server/wiki/Maintenance-and-Release-Schedule)中找到。

提示

要更快地更新到新的大版本或测试版本，您可以根据自己的选择将实例调整为使用 `测试 `渠道。在大版本发布期间，` 测试 `渠道也会无视预发布参数，更早地提供最新的大版本。

社区中的每个人都能从那些选择评估测试版或候选发布版的人的慷慨测试和反馈中获益匪浅，无论是在他们的测试环境中，还是对于大胆的人来说，在真实条件下。

如果你有机会评估一个预最终版本，开发者和整个社区都感谢你！

提示

我们建议你将测试工作集中在验证你每天依赖的功能和特性（以确保它们按预期运行）。然后，如果你愿意，可以考虑评估任何引起你兴趣的新功能。请在[帮助论坛](https://help.nextcloud.com/)上讨论出现的问题，并将疑似错误报告给 [GitHub 仓库 ](https://github.com/nextcloud/server/issues)。

## 降级 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#downgrading)

降级在任何主要版本、维护版本或预发布版本之间均不受官方支持。

## 报告错误 [](https://docs.nextcloud.com/server/latest/admin_manual/release_schedule.html#bug-reporting)

在报告错误之前，请确保您正在运行仍然受支持的主要版本 *并且* 该版本的最新维护版本。

提示

Nextcloud GmbH（该公司的许多核心开发者受雇于此）提供 [Nextcloud 企业服务 ](https://nextcloud.com/enterprise/)，为使用场景关键时提供直接访问 Nextcloud 工程专业知识的途径。他们可以协助您选择最适合您使用案例的主版本（并确保其得到最佳部署）。
