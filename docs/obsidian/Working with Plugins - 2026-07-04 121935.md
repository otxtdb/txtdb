## 正在更新测试版插件

在命令面板中，使用“检查测试版插件的更新并执行更新”功能，即可查看是否有可用更新。系统会自动下载并安装这些更新，之后插件会重新加载，这样你就可以继续进行测试了。

此外，在 BRAT 的设置选项中，你可以指定：在 Obsidian 启动时，自动检查所有测试版插件的更新情况。

更新后的测试版插件可能需要 5 到 15 分钟才能完成更新。这与 GitHub 的信息缓存方式有关。如果开发者宣布有更新可用，你可能需要稍等片刻，然后再检查是否可以下载该更新。

## 基于某个发布版本的冻结版本

BRAT 会持续监控 GitHub 仓库中插件的更新情况，并及时更新这些插件。不过，如果你希望固定某个插件的版本，可以使用“BRAT: Add a beta plugin with frozen version based on a release tag”这一命令。这样，该插件就会保持你指定的版本，而不会随着其他插件的更新而发生变化。

## 看看是否有更新，但不要进行更新。

命令面板中的“仅检查测试版插件的更新情况，但不进行更新”这一命令会检测测试版插件的更新情况，但实际上不会执行任何更新操作。

## 手动更新其中一个插件

请使用命令面板中的“选择单个插件进行更新”命令来更新特定的插件。

## 重新启动插件

你可能不会经常用到这个功能，但对于开发者来说，这确实是个很有用的工具。你可以使用“重新加载插件”命令，强制让命令面板中的插件命令重新加载。

我使用它来进行移动端开发。Obsidian Sync 会将我的代码更改同步到 iPad 上。然后，在 iPad 上，我使用“重启”命令来重新加载插件，而无需重启整个 Obsidian 软件。

你们中的大多数人并不需要这个功能，但对开发人员来说却很有用。我敢打赌，你们都希望我在你们阅读这一部分内容之前就告诉你们这一点。

## 重新安装插件

有时候，已安装的测试版插件可能会损坏，或者你修改了某些文件后，需要重新下载该插件。重新安装命令正是用于处理这种情况的。它会从 GitHub 上获取该插件的测试版版本，然后替换掉你硬盘上原有的插件文件。

## 启用/禁用插件

你可以启用那些当前处于禁用状态的插件，或者禁用那些当前处于启用状态的插件。这样一来，就无需再进入“设置”选项来手动切换这些插件的开关状态了。

## 对于那些喜欢阅读的人来说，这里有一些额外的解释。

首先，你需要知道该测试版插件的 GitHub 仓库地址。其实，这并没有听起来那么复杂。所有插件都是通过 GitHub 来开发的。每位开发者都在 GitHub 上拥有自己的账户，并为自己的插件创建独立的仓库。通常，开发者会主动提供这些信息，不过你也可以凭借自己的思考、推理和理解能力来自行获取这些信息。

这就是你所需要的全部操作。一旦获得了仓库路径，打开命令面板，找到“添加用于测试的测试版插件”（或“添加带有固定版本的测试版插件”）这一命令。随后，系统会提示你输入仓库路径。输入正确后，测试版插件就会被安装到你的系统中。
